# モジュールのひな形

新しいモジュール（実装のファイルと、その試験のファイルの 1 組）を足すときの出発点。形だけを置いてあり、処理の中身は
入れていない。中身のファイルは、プロジェクトの技術に合う部品が置く（部品が無いプロジェクトでは、この文書だけがある）。

## 使い方

1. 置く層を決める（下の「置いてよい層」）。
2. このディレクトリの実装のファイルと試験のファイルを、その層のディレクトリへ写し、ファイルの名前と、中の名前を、作るものに
   合わせて変える。
3. 試験に、作るものの振る舞いを具体的な入力と出力で書いてから、実装を書く。
4. すべての検査（`npm run check`）を通す。

## 置いてよい層

- 層の一覧と、各層の責務は、`ARCHITECTURE.md` の「層と責務」にある。そこに無いディレクトリを作らない。
- 層を足すときは、ひな形を写す前に、設計の正本と検査の規則を直す。

## 守る決まり

- このディレクトリのひな形は、アプリのコードを読み込まず、それだけで検査が通る形に保つ。アプリのコードからも、ここを
  読み込まない。アプリのコードが変わっても、ひな形が壊れないためである。
- 各層が読み込んでよい層と、どの層でも守る決まりは、`ARCHITECTURE.md` にある。
- 検査のコマンドと、秘匿値と個人情報の決まりは、`AGENTS.md` にある。
- 構成やインターフェースを変える作業では、先に計画を書く（`docs/PLANS.md` の「計画をファイルに書く条件」）。
